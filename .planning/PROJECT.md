# 스터디 복습 퀴즈 (Weekly Review Quiz)

## What This Is

6명이 함께하는 복습 스터디용 웹사이트. 매주 금요일, 그 주에 스터디원들이 노션 "개인 복습 기록" 캘린더 DB에 남긴 기록(그리고 선택적으로 업로드된 실습파일·CSV·엑셀)으로 10문제를 자동 출제하고, 6명 모두 같은 문제를 10~20분 동안 푼다. 제출하면 각 문제 위에 정답·짧은 해설·출처가 표시되고, 틀린 문제와 스터디 전체 정답률이 낮은 문제는 별도 공간에 모여 언제든 다시 복습할 수 있다.

## Core Value

매주 금요일, 그 주 6명의 노션 복습 기록만으로 "실제로 배운 내용"에 근거한 10문제 세트가 사람 손 없이 만들어지고, 모두가 같은 문제를 풀고 출처가 달린 해설로 복습할 수 있어야 한다.

### Active

**자동 출제 (Notion → 퀴즈)**
- [ ] 매주 금요일 정해진 시각에 자동으로 그 주(월~일, `날짜` 속성 기준)의 "개인 복습 기록" 항목을 노션 API로 가져온다
- [ ] 가져온 기록으로 10문제 공통 세트를 생성해 6명 모두에게 동일하게 제공한다
- [ ] 문제 구성: 7문제 = 중요 키워드의 개념 + 실무에서의 쓰임 / 3문제 = 분석 코드를 보고 어떤 분석 단계·어떤 분석 목적에 쓰였는지 묻는 더 어려운 문제
- [ ] 문제 형식: 객관식 + 단답형이 기본, 서술형이 이해도를 더 잘 확인할 수 있는 문제(주로 코드 분석)는 서술형 포함
- [ ] 예상 풀이 시간 10~20분에 맞춘 분량과 난이도
- [ ] 그 주 기록이 부족하거나 출제가 실패하면 실패 사실이 사이트에 드러나고 수동 재시도가 가능하다

**자료 업로드 (선택)**
- [ ] 금요일 출제 전까지 스터디원 누구나 실습파일·CSV·엑셀을 업로드할 수 있다
- [ ] 업로드된 파일은 그 주 출제에 노션 기록과 함께 반영된다
- [ ] 업로드가 없으면 노션 기록만으로 10문제를 구성한다

**풀이·채점·해설**
- [ ] 스터디원이 그 주 세트를 풀고 한 번에 제출한다
- [ ] 객관식은 자동 채점, 단답형·서술형은 AI가 채점하고 짧은 피드백을 준다
- [ ] 제출 후 각 문제 위에 정답 여부·정답이 표시된다
- [ ] 해설은 최대 5줄 요약 + 관련 개념 출처 + 노션 기록 출처(작성자 칸의 이름 + 날짜, 예: "이주현 · 10/14") 또는 실습 데이터 출처(파일명)

**오답 복습 공간**
- [ ] "내가 틀린 문제" 탭: 본인이 틀린 문제를 주차와 상관없이 한눈에 모아 본다
- [ ] "스터디 전체 정답률 낮은 문제" 탭: 6명 기준 정답률이 낮은 문제를 모아 본다
- [ ] 언제든 들어가서 문제·정답·해설을 다시 볼 수 있다

**함께 쓰기**
- [ ] 구글 로그인, 등록된 6명의 이메일만 접속 가능
- [ ] 문제별 정답률 등 스터디 전체 결과를 볼 수 있다

### Out of Scope

- 개인별로 다른 문제 세트 / 버튼으로 즉석 출제 — 모두 같은 문제를 풀어야 정답률 비교가 의미 있음 (사용자 결정)
- 노션에 결과를 다시 쓰기(write-back) — 노션은 읽기 전용 소스로 충분, 권한·구조 복잡도만 늘어남
- 노션 외 다른 메모 도구 연동 — 스터디가 노션만 사용
- 6명 이외 공개 가입 — 스터디 내부용
- 모바일 앱 — 웹(모바일 브라우저 대응)으로 충분

## Context

**노션 구조 (사용자 스크린샷으로 확인):**
- "Study Section" 페이지 안의 "개인 복습" 영역에 **"개인 복습 기록" 데이터베이스**가 캘린더 뷰로 있음
- 항목 1개 = 스터디원 1명의 하루 복습 글. 2026-10-13~15에 6명이 매일 작성 (주당 최대 ~30개 항목 예상)
- 속성: `작성자`(사람), `과목`(선택), `날짜`(날짜), `오늘의 학습 기록`(텍스트)
- 캘린더에서 날짜의 +를 누르면 템플릿이 자동 생성됨. 본문 템플릿:
  - 01. 오늘 배운 내용 — `핵심 개념`(리스트), `내 말로 설명`(리스트), `직접 작성한 코드`(코드 블록)
  - 02. 어려웠던 내용 — 어떤 부분이 어려웠나 / 처음 내가 생각한 방법 / 막힌 이유
  - 03. 해결 방법 — 해결 과정 / AI에게 물어봤다면 AI는 어떻게 답했는지 / 최종 코드 또는 정답(코드 블록)
  - 04. 한 줄 인사이트 — 무엇을 알게 되었는지
- 출제 매핑: 핵심 개념·내 말로 설명 → 개념 7문제 / 직접 작성한 코드·최종 코드 → 코드 분석 3문제 / 어려웠던 내용·막힌 이유 → 헷갈리는 오답 보기(distractor) 소재
- 템플릿의 `작성자` 칸이 기본값으로 비어 있음 → 출처 표시는 작성자 칸에 의존하므로 스터디원이 작성자 칸을 채워야 함 (비었을 때의 처리 필요)

**노션 계정 상태:** 무료 플랜, 1명이 워크스페이스 소유자, 나머지 5명은 게스트, 전체 허용. 노션 API 통합(internal integration)은 워크스페이스 소유자만 만들 수 있으므로 소유자가 통합을 만들고 "개인 복습 기록" DB에 연결해야 함.

**학습 도메인:** 데이터 분석 스터디(코드 기반 분석 실습). "분석 단계"는 데이터 수집·전처리·EDA·모델링·평가 등 분석 흐름의 단계를 뜻함.

**개발 환경:** Windows 11, Node v25.7.0. 프로젝트 폴더 `C:\Users\User\Desktop\Claude`에 Claude Code 스킬 설치됨 — notion-api, supabase, agent-browser, design-taste-frontend, mcp-builder, find-skills, (기본) claude-api.

## Constraints

- **Design**: 화면 디자인 기준은 design-taste-frontend 스킬 — 단, 이 스킬은 공개 웹페이지용(대시보드·앱 화면 제외)이므로 첫 화면·전체 아트 디렉션(타이포·색·여백)에 적용하고 퀴즈/오답 화면은 그 기준을 따르도록 확장
- **Notion**: 무료 플랜 + 게스트 구조 — 통합 생성·DB 연결은 소유자 1명이 해야 함. API 속도 제한(평균 초당 3회) 고려
- **Users**: 정확히 6명, 동시 사용 규모 작음 — 무료 티어 인프라로 충분해야 함
- **Cost**: 스터디 운영용이므로 월 비용 최소화 (무료 티어 우선, AI 호출은 주 1회 출제 + 채점 정도)
- **Security**: 노션 토큰·AI API 키는 서버에만 보관, 브라우저로 노출 금지. 6명 이메일 외 접근 차단
- **Language**: 사이트 UI·문제·해설 모두 한국어
