# Requirements: 스터디 복습 퀴즈 (Weekly Review Quiz)

**Defined:** 2026-10-16 (rewritten after pivot to static site)
**Core Value:** 매주 그 주 6명의 노션 복습 기록에 근거한 10문제 세트가 링크 하나로 공유되고, 모두가 같은 문제를 풀고 출처가 달린 해설로 복습할 수 있어야 한다 — 비용 0원, 서버 없이.

## v1 Requirements

### Quiz Format (문제 형식·데이터)

- [x] **FMT-01**: 한 주 세트는 JSON 파일 1개이며 주차·출제 범위·출처 목록·10문제를 담는다
- [x] **FMT-02**: 각 문제는 객관식(보기 4개, 정답 1개) 또는 단답형(인정 정답 목록) 중 하나다
- [x] **FMT-03**: 각 문제는 유형(개념 / 코드 분석), 문제, (코드 분석이면) 코드 원문, 정답, 최대 5줄 해설, 관련 개념 출처, 노션 출처("작성자 · 날짜") 또는 실습 파일명을 가진다
- [x] **FMT-04**: 검사 스크립트가 세트를 검사한다 — 10문제, 개념 7 + 코드 분석 3, 객관식 보기 4개·중복 없음·정답 범위 내, 단답형 인정 정답 1개 이상, 해설 5줄 이내, 출처가 입력 기록 목록에 존재, 코드 분석 문제의 코드가 입력 원문과 일치
- [x] **FMT-05**: 사이트는 주차 목록 파일을 읽어 이번 주 세트와 지난 주차 세트를 찾는다

### Generation (주간 출제 스킬)

- [ ] **GEN-01**: 승환은 Claude Code에서 "이번 주 퀴즈 만들어 줘"로 프로젝트 스킬을 실행하고, 노션 Markdown 내보내기 폴더·붙여넣은 내용·실습 파일(.py, .ipynb, .csv, .xlsx)을 입력으로 줄 수 있다
- [ ] **GEN-02**: 스킬은 출제 주 범위(`날짜`가 지난주 금요일 ~ 이번 주 금요일, 직전 세트에 쓰이지 않은 기록)에 맞는 기록만 사용한다
- [ ] **GEN-03**: 템플릿 기본 문구("리스트", "# 여기에 코드", 빈 항목)는 출제 재료에서 제외된다
- [ ] **GEN-04**: 7문제는 중요 키워드의 개념 + 실무에서의 쓰임, 3문제는 기록 속 분석 코드를 보고 어떤 분석 단계·목적인지 묻는 더 어려운 문제로 만든다
- [ ] **GEN-05**: 객관식 오답 보기에 스터디원의 "어려웠던 내용 / 막힌 이유"가 반영된다
- [ ] **GEN-06**: 예상 풀이 시간이 10~20분이 되도록 분량을 맞춘다
- [ ] **GEN-07**: 스킬은 만든 세트를 검사 스크립트로 확인하고, 통과하지 못하면 고쳐서 다시 검사한다
- [ ] **GEN-08**: 업로드 파일이 있으면 노션 기록과 함께 재료로 쓰고 해설 출처에 파일명을 표시하며, 없으면 노션 기록만으로 구성한다. 한글 CSV(CP949/EUC-KR)도 읽힌다
- [ ] **GEN-09**: 그 주 기록이 너무 적으면(기록 6개 또는 작성자 3명 미만) 스킬이 승환에게 알리고 진행 여부를 묻는다
- [ ] **GEN-10**: 스킬은 통과한 세트를 주차 목록에 추가하고 커밋·푸시까지 해서 사이트에 올린다 (승환 확인 후)

### Quiz (풀이)

- [x] **QUIZ-01**: 스터디원은 링크를 열면 로그인 없이 이번 주 세트를 풀 수 있고, 처음 한 번 이름을 고른다(6명 목록)
- [ ] **QUIZ-02**: 10문제를 한 흐름으로 풀 수 있고, 코드는 읽기 쉽게(고정폭 글꼴, 줄바꿈 유지) 표시된다
- [ ] **QUIZ-03**: 풀던 답은 브라우저에 자동 저장되어 창을 닫았다 와도 이어서 풀 수 있다
- [ ] **QUIZ-04**: 제출 전 빈 문항 수를 확인하고, 제출하면 그 세트의 첫 시도 답이 고정된다
- [ ] **QUIZ-05**: 모바일 브라우저에서도 풀이부터 제출까지 가능하다

### Results (채점·해설)

- [x] **RSLT-01**: 제출 즉시 객관식은 정답 번호로, 단답형은 인정 정답 목록과 정규화(앞뒤·중간 공백, 대소문자, 전각/반각) 비교로 자동 채점된다
- [ ] **RSLT-02**: 각 문제 위에 정답 여부와 정답이 표시된다
- [x] **RSLT-03**: 각 문제에 최대 5줄 요약 해설이 표시된다
- [ ] **RSLT-04**: 해설에 관련 개념 출처(개념 이름 + 공식 문서 항목 이름)와 노션 출처("작성자 · 날짜") 또는 실습 파일명이 표시된다
- [ ] **RSLT-05**: 결과 화면에 총점과 개념/코드 분석별 점수가 표시된다

### Review (오답 복습 공간)

- [ ] **REVW-01**: "내가 틀린 문제" 탭에서 이 브라우저에서 첫 시도에 틀린 문제를 주차와 상관없이 한눈에 본다
- [ ] **REVW-02**: "스터디 전체 정답률 낮은 문제" 탭에서 팀 통계 기준 3명 이상 응답하고 정답률 50% 이하인 문제를 "6명 중 N명 정답"과 함께 본다
- [ ] **REVW-03**: 두 탭 모두 문제·정답·해설·출처를 다시 볼 수 있다
- [ ] **REVW-04**: 오답 문제를 다시 풀어볼 수 있고, 다시 푼 결과는 첫 시도 기록·팀 통계에 영향을 주지 않는다
- [ ] **REVW-05**: 지난 주차 세트 목록에서 어떤 주차든 열어 풀거나 결과를 다시 볼 수 있다

### Team Stats (팀 결과 모으기)

- [ ] **TEAM-01**: 결과 화면의 "결과 보내기" 버튼을 누르면 이름·주차·문제별 정오답이 미리 채워진 구글 폼이 열리고, 스터디원은 제출만 누르면 된다
- [ ] **TEAM-02**: 승환은 Claude Code에서 "이번 주 결과 반영해 줘"로 구글 폼 응답(CSV 내보내기)을 주차별 팀 통계 JSON으로 바꾸고 커밋·푸시한다 (같은 사람이 여러 번 보내면 첫 응답만)
- [ ] **TEAM-03**: 사이트 결과 화면에 팀 통계가 있으면 문제별 "6명 중 N명 정답"이 표시된다
- [ ] **TEAM-04**: 구글 폼 만드는 방법과 폼 주소·항목 ID를 사이트 설정에 넣는 방법이 안내 문서로 있다

### Deploy (공유)

- [ ] **DPLY-01**: 사이트는 GitHub 공개 저장소의 GitHub Pages로 배포되고, 링크 하나로 6명이 접속한다
- [ ] **DPLY-02**: 승환용 주간 루틴 안내(노션 내보내기 → 퀴즈 만들기 → 링크 공유 → 결과 반영)가 README에 있다

### Design (화면)

- [ ] **DSGN-01**: 첫 화면과 전체 디자인(글꼴·색·여백)은 design-taste-frontend 기준을 따르고, 퀴즈·결과·오답 화면도 같은 방향으로 맞춘다
- [ ] **DSGN-02**: 모든 화면은 한국어다

## v2 Requirements

- **V2-01**: 팀 워크스페이스가 Claude 노션 커넥터에 연결되면 스킬이 노션을 직접 읽는다 (내보내기 생략)
- **V2-02**: 오답 노트에 "왜 틀렸는지" 개인 메모
- **V2-03**: 오답 문제를 두 번 연속 맞히면 "졸업"
- **V2-04**: 주간 요약(가장 많이 틀린 개념, 정답률 추이) — 포트폴리오용 "6명이 쓰면서 정답률이 이렇게 바뀌었다"
- **V2-05**: 개인 기록 내보내기/가져오기 (기기 이동용 파일)
- **V2-06**: 구글 시트 공개 CSV를 사이트가 직접 읽어 팀 통계 자동 반영

## Out of Scope

| Feature | Reason |
|---------|--------|
| 서버·DB·로그인·AI API | 비용 0원, 정적 사이트 결정 |
| 서술형·자기 채점 | 사용자 결정: 개인이 직접 고르는 상황 제거 |
| 노션 API 자동 연동·금요일 자동 실행 | 팀 DB 연결 권한 없음, 주 1회 수동 실행으로 충분 |
| 정답 숨김 보안 | 정적 JSON에 정답 포함, 신뢰 기반 스터디 |
| 리더보드·시간 제한·실시간 대결 | 복습 목적에 맞지 않음 |
| 모바일 앱 | 모바일 브라우저로 충분 |
