# Requirements: 스터디 복습 퀴즈 (Weekly Review Quiz)

**Defined:** 2026-10-16
**Core Value:** 매주 금요일, 그 주 6명의 노션 복습 기록만으로 "실제로 배운 내용"에 근거한 10문제 세트가 사람 손 없이 만들어지고, 모두가 같은 문제를 풀고 출처가 달린 해설로 복습할 수 있어야 한다.

## v1 Requirements

### Access (접속·권한)

- [ ] **AUTH-01**: 스터디원은 구글 계정으로 로그인하고, 새로고침·재방문 후에도 로그인이 유지된다
- [ ] **AUTH-02**: 등록된 6명의 이메일이 아니면 로그인해도 어떤 데이터도 볼 수 없고 접근 거부 화면을 본다 (DB 수준 RLS로 강제)
- [ ] **AUTH-03**: 각 스터디원 계정은 노션 `작성자` 이름과 연결되어 있다 (members 테이블)
- [ ] **AUTH-04**: 관리자(1명, 노션 워크스페이스 소유자)는 관리자 전용 기능을 쓸 수 있고, 다른 스터디원은 쓸 수 없다

### Ingest (노션 수집)

- [ ] **INGT-01**: 시스템은 노션 "개인 복습 기록" DB에서 출제 주의 기록(KST 기준 월요일 00:00 ~ 금요일 출제 시점, `날짜` 속성)을 모두 가져온다
- [ ] **INGT-02**: 각 기록의 작성자·과목·날짜·본문(핵심 개념, 내 말로 설명, 직접 작성한 코드, 어려웠던 내용, 해결 방법, 한 줄 인사이트)을 코드 블록 원문 그대로 수집한다
- [ ] **INGT-03**: 템플릿 기본 문구("리스트", "# 여기에 코드", 빈 항목)는 출제 재료에서 제거된다
- [ ] **INGT-04**: `작성자`가 비어 있으면 노션 작성 계정 → "작성자 미상" 순으로 대체하고 관리자에게 경고가 표시된다
- [ ] **INGT-05**: 수집 결과는 출제 시점의 스냅샷으로 저장되어, 이후 노션이 수정되어도 출처·해설이 바뀌지 않는다
- [ ] **INGT-06**: 관리자는 출제 전에 "이번 주 수집 결과"(기록 수, 작성자 수, 사용 가능한 코드 블록 수)를 볼 수 있다

### Generation (자동 출제)

- [ ] **GEN-01**: 매주 금요일 18:00~18:59(KST) 사이에 자동으로 그 주 공통 세트 10문제가 생성된다
- [ ] **GEN-02**: 세트는 7문제(중요 키워드 개념 + 실무에서의 쓰임)와 3문제(분석 코드를 보고 어떤 분석 단계·목적인지 묻는 더 어려운 문제)로 구성된다
- [ ] **GEN-03**: 문제 형식은 객관식(4지선다)과 단답형이 기본이며, 코드 분석 문제 중 1문제까지 서술형을 쓸 수 있다
- [ ] **GEN-04**: 코드 문제의 코드는 노션 기록의 코드를 그대로 사용한다 (AI가 고쳐 쓰지 않음)
- [ ] **GEN-05**: 객관식 오답 보기에는 스터디원의 "어려웠던 내용 / 막힌 이유"가 반영된다
- [ ] **GEN-06**: 예상 풀이 시간이 10~20분 범위에 들도록 분량이 조절된다
- [ ] **GEN-07**: 생성된 세트는 자동 검증(문항 수·구성, 보기 4개 중복 없음, 정답 존재, 출처가 실제 기록인지, 해설 5줄 이내)을 통과해야만 공개된다
- [ ] **GEN-08**: 객관식은 AI가 정답을 모르는 상태로 한 번 더 풀어보고, 정답이 둘 이상이거나 다르면 해당 문제를 다시 만든다
- [ ] **GEN-09**: 그 주 기록이 기준(기록 6개, 작성자 3명) 미만이면 출제하지 않고 사이트에 이유가 표시되며, 관리자는 "그래도 출제"를 실행할 수 있다
- [ ] **GEN-10**: 출제는 Claude Opus(claude-opus-5-5)로 하며, 모델은 코드 수정 없이 설정값으로 바꿀 수 있다

### Operations (운영·안정성)

- [ ] **OPS-01**: 홈 화면에 이번 주 세트 상태(대기 / 생성 중 / 실패 / 공개됨)가 표시된다
- [ ] **OPS-02**: 금요일 출제가 실패하면 토·일에 자동으로 다시 시도하고, 관리자는 언제든 수동으로 다시 실행할 수 있다
- [ ] **OPS-03**: 같은 주에 세트가 두 번 만들어지지 않는다 (중복 실행 방지)
- [ ] **OPS-04**: 매일 1회 노션 연결 상태를 점검하고, 연결이 끊기면 관리자에게 표시된다 (무료 DB 휴면 방지 겸용)
- [ ] **OPS-05**: 관리자는 공개된 문제 중 잘못된 문제를 무효 처리할 수 있고, 무효 문제는 점수·정답률에서 제외된다. 아무도 풀지 않았다면 해당 문제만 다시 생성할 수 있다

### Quiz (풀이)

- [ ] **QUIZ-01**: 스터디원은 이번 주 세트 10문제를 한 화면 흐름에서 풀 수 있고, 코드는 읽기 쉽게 표시된다
- [ ] **QUIZ-02**: 풀던 답은 자동 저장되어, 창을 닫았다 와도 이어서 풀 수 있다
- [ ] **QUIZ-03**: 제출 전 빈 문항 수를 확인하는 단계가 있고, 제출하면 답을 바꿀 수 없다
- [ ] **QUIZ-04**: 세트는 다음 주 세트가 공개될 때까지 제출할 수 있다
- [ ] **QUIZ-05**: 제출하기 전에는 정답·해설·다른 사람 결과를 어떤 방법으로도 볼 수 없다 (DB 수준으로 강제)

### Grading (채점)

- [ ] **GRAD-01**: 객관식과 정답이 정확히 일치하는 단답형은 제출 즉시 채점된다
- [ ] **GRAD-02**: 그 외 단답형과 서술형은 출제 때 만든 채점 기준으로 AI가 정답 / 부분 정답 / 오답으로 채점하고 한두 줄 피드백을 준다
- [ ] **GRAD-03**: AI 채점 중인 문제는 "채점 중"으로 표시되고, 실패해도 0점이 아니라 "채점 대기"로 남아 다시 시도된다
- [ ] **GRAD-04**: 채점 결과는 한 번 저장되면 다시 볼 때 바뀌지 않는다
- [ ] **GRAD-05**: 부분 정답은 0.5점으로 계산된다
- [ ] **GRAD-06**: 채점은 Claude Sonnet(claude-sonnet-5-5)으로 하며, 모델은 설정값으로 바꿀 수 있다

### Results (결과·해설)

- [ ] **RSLT-01**: 제출 후 각 문제 위에 정답 여부와 정답이 표시된다
- [ ] **RSLT-02**: 각 문제에 최대 5줄 요약 해설이 표시된다
- [ ] **RSLT-03**: 해설에 관련 개념 출처(개념 이름 + 공식 문서의 해당 항목 이름)가 표시된다
- [ ] **RSLT-04**: 해설에 노션 출처가 "작성자 · 날짜"(예: 이주현 · 10/14) 형식으로 표시되며, 이 값은 AI가 아니라 저장된 기록에서 만들어진다
- [ ] **RSLT-05**: 제출한 스터디원은 문제별 "6명 중 N명 정답"과 누가 제출했는지를 볼 수 있다 (개인 점수는 본인만)
- [ ] **RSLT-06**: 스터디원은 지난 주차 세트와 자기 결과를 다시 볼 수 있다
- [ ] **RSLT-07**: 스터디원은 결과 화면에서 "이 문제 이상해요" 신고를 남길 수 있고, 관리자는 신고 목록을 본다

### Review (오답 복습 공간)

- [ ] **REVW-01**: "내가 틀린 문제" 탭에서 본인이 틀리거나 부분 정답인 문제를 주차와 상관없이 한눈에 본다
- [ ] **REVW-02**: "스터디 전체 정답률 낮은 문제" 탭에서 3명 이상 응답했고 평균 정답률이 50% 이하인 문제를 본다
- [ ] **REVW-03**: 두 탭 모두 문제·정답·해설·출처를 다시 볼 수 있다
- [ ] **REVW-04**: 오답 탭의 문제를 다시 풀어볼 수 있고, 다시 푼 결과는 스터디 정답률에 영향을 주지 않는다

### Uploads (자료 업로드 — 마지막 단계)

- [ ] **UPLD-01**: 스터디원은 금요일 출제 전까지 실습파일(.py, .ipynb), CSV, 엑셀(.xlsx)을 그 주에 올릴 수 있다
- [ ] **UPLD-02**: 올라온 파일은 그 주 출제에 노션 기록과 함께 재료로 쓰이고, 해설 출처에 파일명이 표시된다
- [ ] **UPLD-03**: 한글 CSV(CP949/EUC-KR 포함)가 깨지지 않고 읽히며, 업로드한 사람은 미리보기로 확인할 수 있다
- [ ] **UPLD-04**: 업로드가 없으면 노션 기록만으로 10문제가 구성된다

### Design (화면)

- [ ] **DSGN-01**: 첫 화면과 전체 디자인(글꼴·색·여백)은 design-taste-frontend 기준을 따르고, 퀴즈·결과·오답 화면도 같은 방향으로 맞춘다
- [ ] **DSGN-02**: 모든 화면은 한국어이고 모바일 브라우저에서도 문제 풀이가 가능하다

## v2 Requirements

### Feedback

- **FDBK-01**: 스터디원이 AI 채점 결과에 이의를 신청하고 관리자가 점수를 수정할 수 있다
- **FDBK-02**: 오답 노트에 "왜 틀렸는지" 개인 메모를 남길 수 있다
- **FDBK-03**: 오답 문제를 두 번 연속 맞히면 "졸업" 처리되어 내 오답 탭에서 빠진다

### Insight

- **INSI-01**: 매주 스터디 전체 요약(가장 많이 틀린 개념, 평균 소요 시간)을 본다
- **INSI-02**: 기록이 적은 주에 문제 수를 줄이거나 코드 문제를 빼는 축소 모드로 출제한다
- **INSI-03**: 최근 주차와 거의 같은 문제가 나오지 않도록 중복을 걸러낸다

### Notify

- **NOTF-01**: 출제·마감 알림을 카카오톡/디스코드로 받는다

## Out of Scope

| Feature | Reason |
|---------|--------|
| 개인별 다른 세트 / 버튼으로 즉석 출제 | 모두 같은 문제여야 정답률 비교가 의미 있음 (사용자 결정) |
| 실시간 대결·시간 제한·리더보드 | 복습 목적에 맞지 않고 부담만 늘림 |
| 부정행위 방지 | 6명 지인 스터디, 신뢰 기반 |
| 노션에 결과 다시 쓰기 | 노션은 읽기 전용 소스로 충분, 권한·구조 복잡도 증가 |
| AI가 만든 외부 링크 | 그럴듯한 가짜 URL 위험 — 이름으로 출처 표시 |
| 6명 외 공개 가입 | 스터디 내부용 |
| 모바일 앱 | 모바일 브라우저로 충분 |
| 간격 반복(spaced repetition) 알고리즘 | 주 1회 스터디에는 과함 |
